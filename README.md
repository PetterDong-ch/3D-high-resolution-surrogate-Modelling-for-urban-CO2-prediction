# Advanced Machine Learning for Urban Atmospheric Flow Prediction and Environmental Management

The main scientific artefacts are three reproducibility packages:

| Package | Purpose | Main result |
|---|---|---|
| `final_model_v40/` | Final Camden spatial CO2 surrogate. Predicts one-step 3-D CO2 increments on 16 x 256 x 256 tiles with full-domain context. | 40-sample report evaluation: R = 0.9711, R2 = 0.9405, MAE = 2.4651 ppm, RMSE = 4.2943 ppm. |
| `final_model_twostage_v6/` | Final two-stage Camden surrogate. Stage 1 predicts meteorological fields, then Stage 2 feeds those predictions into the CO2 surrogate. | Stage-2 validation evaluation: reconstructed CO2 R = 0.9590, R2 = 0.9197, MAE = 1.8310 ppm, RMSE = 3.3335 ppm. |
| `final_model_task2_v3/` | Height-resolved horizontal-mean CO2 profile surrogate for Camden and Richmond. | Camden: R = 0.9931, R2 = 0.9862. Richmond fine-tuned: R = 0.9832, R2 = 0.9668. |

Each package has its own `README.md`, locked dependencies, environment file,
configuration files, released checkpoints, verification script and ordered
preprocessing/training/evaluation commands. The package README files are the
authoritative instructions for reproducing each result.

## Quick Start

Use Git LFS before cloning or pulling, because released checkpoints and other
large binary artefacts are stored through LFS.

```bash
git lfs install
git clone https://github.com/PetterDong-ch 3D-high-resolution-surrogate-Modelling-for-urban-CO2-prediction.git
cd 3D-high-resolution-surrogate-Modelling-for-urban-CO2-prediction
git lfs pull
```

The checkpoint manifests can be checked without the external PALM data:

```bash
cd final_model_v40
python3 scripts/verify_package.py

cd ../final_model_twostage_v6
python3 scripts/verify_package.py

cd ../final_model_task2_v3
python3 scripts/verify_package.py
```

After the external data have been obtained and placed in the documented
locations, pass `--data-root` to the relevant verifier as described in each
package README.

## Data Access

The raw PALM NetCDF simulations and generated caches are too large for GitHub
and are not redistributed in this repository. Authorised academic users should
request the relevant Camden and Richmond PALM data from:

```text
Linfeng Li <l.li20@imperial.ac.uk>
```

When requesting access, identify this IRP and the required PALM domains. Access
and reuse remain subject to the data owner's approval. Once access is granted,
place or link the data using the contracts below:

| Package | Data contract |
|---|---|
| `final_model_v40/` | `final_model_v40/docs/data_paths.md` |
| `final_model_twostage_v6/` | `final_model_twostage_v6/docs/data_paths.md` |
| `final_model_task2_v3/` | `final_model_task2_v3/docs/data_paths.md` |

Generated caches, sidecars, runs and evaluation outputs should not be treated
as source data. They can be regenerated by the scripts in the package
`scripts/` directories and are ignored by Git where appropriate.

## Environments

The reference Python version for the final packages is Python 3.12.3. Each
package provides both `environment.yml` and `requirements-lock.txt`.

Typical Conda setup:

```bash
cd final_model_v40
conda env create -f environment.yml
conda activate final-model-v40
python scripts/verify_package.py
```

Repeat with the package-specific environment files for:

```text
final_model_twostage_v6/environment.yml
final_model_task2_v3/environment.yml
```

Avoid mixing these environments with server-wide `PYTHONPATH` overlays or
unrecorded site packages. CUDA, cuDNN, GPU model and PyTorch build differences
can cause small numerical differences even when seeds are fixed.

## Full Reproduction Order

Run the workflows below from a clean clone after installing dependencies and
arranging the external data.

For the final V40 Camden spatial surrogate:

```bash
cd final_model_v40
python scripts/verify_package.py --data-root external_data
bash scripts/prepare_camden_data.sh
bash scripts/reproduce_camden_training.sh
bash scripts/reproduce_camden_report_evaluation.sh
```

For the final two-stage Camden surrogate:

```bash
cd final_model_twostage_v6
python scripts/verify_package.py --data-root external_data
bash scripts/prepare_stage1_data.sh
bash scripts/reproduce_stage1_training.sh
bash scripts/prepare_stage2_data.sh
bash scripts/reproduce_stage2_training.sh
bash scripts/reproduce_report_evaluation.sh
```

For the final Task2 height-resolved profile surrogate:

```bash
cd final_model_task2_v3
python scripts/verify_package.py --data-root external_data
bash scripts/train_camden_task2_v3.sh
bash scripts/evaluate_camden_task2_v3.sh
bash scripts/train_richmond_finetune_task2_v3.sh
bash scripts/evaluate_richmond_task2_v3.sh
```

The Task2 profile caches can be regenerated with
`scripts/prepare_profile_cache.sh` once the required spatial caches and sidecars
have been produced or supplied. See `final_model_task2_v3/docs/data_paths.md`
for the exact cache contract.

## Randomness and Hardware Variability

The final workflows fix seeds and request deterministic CUDA/cuDNN behaviour
where supported:

| Package | Seed |
|---|---:|
| `final_model_v40/` | 42, with cache generation seed 3300 |
| `final_model_twostage_v6/` | 42 |
| `final_model_task2_v3/` | 123 |

Training uses stochastic optimisation and GPU kernels, so bit-for-bit identical
retrained checkpoints are not guaranteed across machines. Reproduction should
be assessed using the same data splits, sample counts, checkpoint hashes for
released models, qualitative outputs and statistically equivalent metrics.


## Confidentiality and External Data

This repository does not include confidential or oversized PALM archives. The
code, configuration, manifests and instructions needed to regenerate the
results are included, while the external data access path is documented above
and in each package.
